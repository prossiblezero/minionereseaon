# 方法、验收与结果边界

## 数据与评测

官方推荐 SFT 的 102 个分片共有 48,269 条记录；目录名称包含 Video，但最终答案覆盖四个领域，商品答案共有 3,988 条。消息是 JSON 字符串，内容又是文本块列表。解析仅使用用户输入和 assistant 最后 `</think>` 之后的商品答案；`sid_token_list`、目标描述和目标标签均不进入输入构造函数。

所有划分先按去除任务请求的历史上下文分组，使用 SHA256(group_id + "42") 的模 100 值划分 80/10/10。完全相同历史与目标的训练重复记录剔除；验证、测试中的重复记录保留在同一组，区间估计按组重采样。来源快照、文件、行号和 record_id 保留在规范化记录中。这不构成严格用户互斥或全局时间切分，基础模型的预训练重叠也无法排除。

训练与评测主集合使用同一有效 CoT 子集：不保留目录外目标；不保留引用了裁剪掉的历史的 CoT；不截断超过 1,024 token 的监督答案来制造有效标签。过滤会改变样本分布，最终计数和原因以 data_report_main.json 为准。主训练集为 2,647 条；目标规模上限不通过复制补足。

这里的“有效”指边界、引用与长度通过检查，不代表已经人工确认每段原始推理的事实正确性。最终验证集为 385 条、测试集为 403 条；训练集哈希在补充去重审计前后保持一致，共同验证监测列表也已冻结。

商品目录来自全部 198 个独立 Pid2Sid 分片，包含约 1,030 万个不同商品 SID。碰撞按不同 (PID, SID) 对核实，同一 SID 不能保证唯一定位一个原始商品。评测在 SID 层面进行。只知道一个监督目标时，Recall@K 与 Pass@K 相同；没有把采样顺序当排序顺序计算 NDCG。

生成输出按原始尝试顺序评分：错误领域、缺失或多个 SID、未闭合的推理、目录外 SID 均是失败尝试；重复 SID 仍占一次尝试，命中集合去重。只在推理中出现目标不算命中。配对区间按 group_id 做 1,000 次 bootstrap，差值方向为后一个设置减前一个设置。

## 监督训练

每个基础样本展开两次。direct 两次都监督目标 SID；mixed 一次直接监督、一次监督原始推理与目标。用户提示和 padding 的 label 为 -100，使用 Qwen3 官方聊天模板及已有 SID token；模型的可训练参数是约 1,009 万个 LoRA 参数。

采用 BF16、micro batch 1、梯度累积 16、梯度检查点，关闭训练 KV cache。逐优化步骤统计处理 token 和监督 token。每 200 步以及训练结束在固定监测子集计算 non-thinking Recall@32；同分保留较早的检查点。主线不同模型使用同一监测集合。选定权重对应的 token 记录存于 selected/training.json。

direct_tokenmatched 以选定 mixed 检查点实际处理过的 token 为预算，使用到达该预算的末次权重；最多超出最后一个优化批次（16 个微批次）。token 相同不代表 FLOPs 严格相同。

该控制组的 warmup 与线性衰减按累计 token 占预算的比例调度，确保到达 token 预算时完成衰减；不沿用为了容纳重复数据而设置的更长 epoch 上限来调度学习率。

## 推理预算与路由

推理预算为 0、128、256、512、1024；达到预算时插入已核对的 Qwen3 `</think>` 和答案换行边界，再独立生成最终答案。强制边界不计为模型生成 token。记录推理 token 均值/P95、无效比例、总生成量和耗时。

路由先生成 8 次 non-thinking，使用第一级 SID 的分散度或原始历史事件数作信号。阈值在验证集冻结，名义 thinking 比例为 25%/50%；测试集实际比例可以不同。随机对照使用测试中实际选中的同等用户数。

非 thinking 用户复用前 8 个答案并补充 24 个新答案；thinking 用户的最终 32 个答案来自思考分支，前 8 个探测答案不进入命中集合，但计入成本。实验采用保存实际 8/24/32 次调用后重放路由的方式，各设置共享随机样本以便配对比较。耗时是实际调用耗时之和，不包含路由控制器的少量开销；生成 token 统计包含被丢弃的探测。16+16 参考组分别使用两种模式各 16 次。

## 稀疏奖励与 RL

std 使用 TRL GRPOTrainer，每提示 8 条完整轨迹、生成批量 8、优化微批次 1、梯度累积 8。续跑新增 std32：每提示 32 条完整轨迹、生成批量与梯度累积均为 32，其他设置相同。TRL 0.24 默认关闭 LoRA 来构造参考策略会回到原始预训练模型；本实现显式加载冻结的 SFT 模型作为参考，并验证初始适配器权重相同。解码显式保留特殊 token，避免 TRL 默认解码丢掉 SID。

正式 RL 训练前冻结共同的 500 个训练输入顺序，保存为 `artifacts/rl_prompt_schedule_main_42.json`。该顺序按 seed 42 有放回抽样，标准 GRPO 关闭额外数据打乱，N×K 的随机状态与这份顺序逐步核对。因此各变体在第 t 步看到同一训练样本；采样后端、生成随机数消耗和损失归一化仍有差异，不宣称所有变量都已完全隔离。

N×K 使用 N=4 条推理，每条推理分出 K=8 个答案。32 条轨迹在同一提示内用总体标准差归一化优势；每个答案使用自己的优势，每段共享推理仅出现一次，优势为其 8 个答案优势的均值。提示及强制插入的边界不计入生成损失。分支信用分配与两提示手算检查见 tests/test_pipeline.py。

前缀奖励只对目录内合法单商品答案生效：全码相同 1.0、前两级相同 0.5、仅第一级相同 0.2，其余 0。可选多样性乘子为同一推理下 `max(0,m-1)/(K-1)`。不奖励推理长度或文风。

策略、冻结 SFT 参考和 rollout 权重具有明确路径。N×K 在共享卡上顺序执行 rollout 与更新。v2 复用 vLLM 的 sleep/wake：每步重新加载当前适配器，更新时卸载推理引擎显存，不沿用旧 LoRA 或前缀缓存。策略、优化器及随机状态逐步保存；训练模式关闭 dropout 并启用梯度检查点。两种实现均使用恒定学习率 5e-6、KL 系数 0.02、clip 0.2 和零权重衰减。N×K 每次优化覆盖一个提示，梯度按生成 token 归一化；该损失归一化和共享推理分配是本项目选择，不能写成论文全部 RL 公式的逐项复现。

先检测最多 256 个训练提示的有效奖励组。低于 1% 时保存解析、截断、目录覆盖检查并跳过训练。日志记录精确命中、非精确前缀命中、第一层码熵/覆盖、训练热门码占比、KL、无效比例、生成 token 和耗时。奖励上升不等于验证召回提升。

本项目没有复现论文的分段 clipping、负样本降权、多领域教师整合、RFT 或完整预训练流程。

N×K 生成使用 vLLM，损失使用 Transformers，log-prob 按相同 temperature=0.8 计算；没有额外实现跨后端数值差异的重要性修正。奖励无差异的组仍保留 KL 正则，不能把这种更新当成来自命中奖励的学习信号。

## 历史与传统基线

三种历史策略按实际 tokenizer 成本分配预算、完整保留事件并恢复输入顺序。recent 使用输入列表尾部优先；domain_recent 给商品约一半预算；balanced 给尾部事件约一半、补充商品约四分之一、未覆盖兴趣组约四分之一。没有时间戳的公开样本仅能按呈现顺序处理，不能把该顺序声称为已验证的全局时间顺序。

历史主预算必须满足至少 30% 的测试输入需要裁剪。2×2 一致性对照在这一预算上额外训练 recent 和 balanced，使用两者都能完整保留 CoT 引用的公共训练子集。与原方案相比增加一个 recent 控制适配器，避免把训练预算不同或训练样本不同误判成历史策略收益。

热门商品仅使用训练目标计数。SASRec 使用两层因果 Transformer，输入同一历史选择结果中的 SID 序列，最大 200 个事件；无文本预训练，用最终目标的正负样本损失训练，在独立完整商品目录上分块打分。采用稀疏物品梯度以控制约千万物品的优化内存。该实现使用 next-target 监督，区别于同时对每个历史位置进行 next-item 监督的另一种 SASRec 训练配方。热门和 SASRec 是确定性 top-K 检索，报告中与生成式尝试预算分别注明协议。

## 资源、执行与简历使用

初期使用的 RTX 4090 与既有其他用户任务共享。初始另一个任务使用约 5.7GB；本项目不停止或修改它。SFT 冒烟的峰值显存约 7.1GiB，正式训练与评测显存仍按日志记录。所有 GPU 阶段串行执行；大文件、虚拟环境和缓存统一保存在 /data1/dzh/minionereason。

本机同步器只拉取项目代码和小型报告，验证 SSH 主机密钥，私钥口令只在进程内存中使用。流水线失败会停止后续实验并同步失败状态；已完成的原始预测和检查点保留。

服务器训练与评测是独立后台进程，SSH 断开后继续执行。本机同步使用受会话管理的持续进程；如果客户端关闭或同步进程结束，需要重新运行 ops/sync_remote.py 才能继续拉取，服务器上的实验结果仍保留。

简历可以描述实际做过的方法、工程实现和问题分析。只有正式测试结果和区间已经产出时才填写提升百分比；没有收益、全零奖励或共享硬件下的局限都应如实说明。
