# MiniOneReason：实验结果与来源

这份备忘统一[项目故事](项目故事-MiniOneReason.md)、[项目深挖](项目深挖-MiniOneReason.md)和 [README](../README.md) 的数字口径。依据截至 **2026-10-24** 的本地源码、`results_v2` 主实验和 `checks` 补充评测；本文没有增加模型训练或生成实验。

## 1. 先分清四套比较

| 比较 | 数据与生成方式 | 回答的问题 | 主要证据 |
| --- | --- | --- | --- |
| 主模型对照 | 本地测试 403 条；每条采样 64 次，取前 8/32/64 次评分 | SFT 和各 RL 变体怎样改变命中率 | [主报告](../reports/PROJECT_REPORT.md)、[逐项结果](../reports/results_v2/) |

| 非思考多采样 | 固定 seed 42 的两组权重；采样 offset 0–4 | 观察到的差值是否依赖某一次生成采样 | [采样统计](../reports/checks/eval_seed_summary.json) |

## 4. 稀疏奖励探针与分支训练

| 变体 | 每提示的答案结构 | 有奖励差异的组 | 精确命中 / 尝试 |
| --- | --- | ---: | ---: |
| std | 8 条完整轨迹 | 3.12% | 0.684% |
| std32 | 32 条完整轨迹 | 5.47% | 0.549% |
| nk | 4 段推理 × 8 个答案 | 5.47% | 0.830% |
| nk_prefix | 同一批 N×K 输出，改用前缀奖励 | 22.66% | 0.830% |

来源：[训练奖励探针](../reports/rl/main_probe_summary_42.json)。分母是最多 256 个真实训练提示；有效组定义为组内奖励标准差大于 `1e-8`。前缀奖励把同一批输出中的部分错误答案变成不同等级，因此 `nk` 和 `nk_prefix` 的精确命中率相同，有效组比例不同。

奖励：目录内完整 SID 精确命中为 1.0，前两级相同为 0.5，仅第一级相同为 0.2，其余为 0。训练门槛是有效组比例至少 1%；四个正式变体都通过。`nk_prefix_div` 有探针与实现，未进入默认四组训练队列。

训练配置：共同的 500 个输入顺序，学习率 `5e-6`、clip `0.2`、KL 系数 `0.02`。来源：[train.py](../train.py#L143)、[配置](../config.json)、[输入顺序](../artifacts/rl_prompt_schedule_main_42.json)。

## 5. 多采样与有效性分解

### 同一权重，五次非思考采样

| 指标 | mixed SFT | RL prefix |
| --- | ---: | ---: |
| 平均 Recall@32 | 1.836% | 3.474% |
| 五次采样 Recall@32 的样本标准差 | 0.222 pp | 0.304 pp |
| 平均无效比例 | 38.837% | 29.875% |
| 平均有效比例 | 61.163% | 70.125% |

五次配对差值依次为 **+1.489、+1.737、+1.241、+1.489、+2.233 pp**。先对每条样本的五次命中取均值，再按输入组重采样，得到合并差 **+1.638 pp，95% CI [0.500, 3.027]**。

来源：[M2 统计](../reports/checks/eval_seed_summary.json)、[补充报告](../reports/checks/CHECKS_REPORT.md)。这五次改变的是生成采样 offset，训练权重始终来自 seed 42。

### 相同有效尝试数

程序从已经生成的 64 次尝试中，按顺序取前 8/16 个合法答案；重复合法答案仍占尝试次数。没有为此追加模型调用。

下表的 M1 区间按 sample_id 做 1,000 次配对 bootstrap；主模型对照与 M2 则按 group_id 重采样。

| 模式 | 两模型共同合格样本 | 等有效预算 Recall@16 差值 | 95% CI，pp |
| --- | ---: | ---: | --- |
| non-thinking，五次采样交集 | 393 / 403 | +0.560 pp | [−0.458, 1.578] |
| thinking，offset 0 | 396 / 403 | +1.768 pp | [0.253, 3.535] |

非思考模式中，目录有效性提升是最清楚的变化；等 16 个有效答案后的差值区间跨零。思考模式在同一条件分析中仍保留正向差值。来源：[M1 分解](../reports/checks/validity_decomposition.json)、[判定规则及解释](../reports/checks/CHECKS_REPORT.md)。

这项分析按“双方拥有足够有效答案”筛选样本，回答的是该子集内的条件问题；它不把总收益严格拆成可相加的因果贡献。

## 6. 推理成本、路由与历史

### RL prefix：32 次最终尝试

| 思考预算 | Recall@32 | 生成 token / 输入 |
| ---: | ---: | ---: |
| 0 | 2.978% | 160.0 |
| 128 | 3.474% | 4,256.3 |
| 256 | 3.474% | 8,345.8 |
| 512 | 3.722% | 16,523.2 |
| 1024 | 3.722% | 24,635.3 |

512 与 1024 在本次测试的召回相同，512 的生成 token 约少 **32.93%**。它是这两个已运行设置的成本比较；路由所用的 **256** token 由验证集选定。

路由的同源全非思考对照由实际 8＋24 次调用合并，Recall@32 为 **4.963%**，160.0 token/输入。各 RL 路由为 4.467% 或 4.963%，未超过这组对照。单次 32 候选的 budget 0 为 2.978%，对应另一组随机序列。来源：[RL 成本与路由汇总](../reports/main_rl_nk_prefix_thinking_42_test_summary.json)。

### 两项训练控制

- token 匹配 direct：预算 **3,958,467**，实际处理 **3,970,388** token，超出约 **0.301%**，停止点是完整梯度累积步骤结束，使用预算终点权重。预算来自 selected mixed 检查点。测试 Recall@32 为 **3.226%（13/403）**，相对 mixed 非思考的差值 **+1.241 pp，95% CI [−0.267, 2.949]**。来源：[训练账本](../reports/training/main_direct_tokenmatched_42_complete.json)、[测试结果](../reports/results_v2/direct_tokenmatched_42_test_recent_in2048_thinkFalse_budgetNone_n64_vllm.json)、[配对比较](../reports/PROJECT_REPORT.md)。
- 历史实验：2,048 token 下 test 裁剪比例 0%，1,024 下 **34.243%**，因此主历史对照采用 1,024。recent/balanced 训练 × recent/balanced 评测使用公共训练子集，两组都是 recent 1.489%、balanced 1.985%，相应差值区间跨零。来源：[长度报告](../reports/data_report_main.json)、[历史门槛](../reports/history_gate_main.json)、[主报告](../reports/PROJECT_REPORT.md)。

## 8. 解释结果时统一使用的条件

1. **训练与统计**：主训练 seed 42；403 条 test 包含 314 个输入组。五个采样 offset 衡量固定权重的生成波动。bootstrap 区间刻画当前样本与分组口径下的差值，未做多重比较校正。
2. **数据范围**：输入历史分组留出；公开样本没有可供本项目核实的完整用户标识和时间戳，预训练数据重叠未核实。传统基线的 test 目标中，3 条曾作为训练目标，353 条在训练目标及历史中均未出现，因此其全零结果主要用于解释训练支持。见[支持度审计](../reports/baseline_support_audit.json)。
3. **资源条件**：主训练和主对照在共享 RTX 4090，后续评测在 RTX 5090；采样 offset 0 与新增 offset 也跨设备。成本主张优先使用生成 token，耗时保留运行记录。
4. **方法范围**：本项目完成数据适配、LoRA SFT、四种 RL 对照、预算/路由、历史实验及外部评测；原论文的完整预训练、RFT、多教师流程与线上 A/B 属于后续扩展。
5. **推理质量**：6 个验证案例中出现输入未提供的日期、搜索行为和历史引用；命中与推理忠实性分开评价。见[案例检查](../reports/case_review.md)。
